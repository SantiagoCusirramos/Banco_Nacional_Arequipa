Comprueba rama, HEAD, `git status` y cualquier cambio no confirmado. **Registra cada modificación del repositorio, incluso documental, en `Documents/solicitud-credito/change-log.md`, sin sobrescribir historia.** No commits/push/merge, comandos destructivos ni cambios en otros módulos sin autorización. Toda nueva documentación va a `Documents/solicitud-credito/`. Cada acción debe distinguir evidencia REAL, SIMULADA, fake y no ejecutada.

**Objetivo:** validar todo lo realizado y preparar una entrega revisable, sin equiparar simulación con integración institucional.

1. Verifica HEAD, rama, `git status`, diff respecto a base disponible (sin modificar Git), historial y documentación. Inspecciona scripts de pruebas ANTES de ejecutarlos: `./bna test` puede limpiar volúmenes; `./bna smoke` puede crear clientes/movimientos. Ejecutar solo con aislamiento probado y autorización. Nunca `docker compose down -v`, `./bna reset`, migraciones destructivas o SQL contra BDs compartidas.
2. Ejecuta suite SOL completa con SQLite y tests focalizados; con instancia MySQL de pruebas aislada verifica migraciones, transacciones y versionado. Ejecutar build/lint/tests frontend si su configuración es segura. Distingue tests fake HTTP, CORE/COREDB reales autorizados, CAP/EVA reales, E2E con browser y los que no se pudieron ejecutar.
3. Escenario E2E objetivo: cliente habilitado → preview → crear → calendario → enviar → espera/acuse → EVA observa → nueva versión de subsanación → reenvío → resultado → auditoría. Etiqueta qué pasos provienen de SIMULADO/mock y cuáles de proveedores reales.
4. Produce matriz de RF-SOL-001..010 y CR-INT-01/02/03/10 con estado `implementado_local`, `preparado_para_integracion`, `integrado_real`, `bloqueado_decision`, líneas de código, comandos de prueba, resultado y asuntos DA-SOL pendientes. Indica objetivamente cuántos RF cumplen la parte técnica; **no afirmar 10/10 si pago doble u otro requisito sigue bloqueado**.
5. Exportar OpenAPI desde aplicación y crear guía de consumo para Captación, Evaluación, Seguridad y frontend: endpoint, propietario, JSON, JWT/token, errores, versiones, callback, idempotencia, URL local, variables y Docker Compose. Confirmar que documentos/contratos no son secretos ni políticas aprobadas por su mera publicación.
6. Auditoría final: evitar datos personales, contraseñas, `.env`, dumps, conflictos con compañeros y cambios fuera de SOL; `git diff --check`, pruebas regresión; preparar rollback y resumen de PR, sin ejecutar commit, push ni abrir PR salvo autorización.

**Entregables:** `sol-evidencias-testing.md`, `sol-entrega-final.md`, OpenAPI verificado si factible, matrices finales y changelog. **Aceptación:** entrega reproducible, lista clara de bloqueos institucionales y siguiente acción precisa por equipo proveedor.
